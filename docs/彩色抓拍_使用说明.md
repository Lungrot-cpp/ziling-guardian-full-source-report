# 原网站彩色事件抓拍

2026-11-01：代码与软件编译完成，当前改动尚未加载板卡或写入Flash。板卡目前运行此前已固化的网口视频版。软件产物与验证依据见 `validation/color-snapshot-result.json`，既有 `flash/manifest.json` 仍描述此前固化版本。

新功能：在原网站 `http://192.168.0.2/` 的“最近事件”里，疑似异常与规则报警附带检测同帧的96×54彩色缩略图，点击打开完整小图。保留当前页面布局，图片完整显示，不裁切。图片本身没有新增检测框叠加。

## 使用

1. 更新本次 `recognition/software/build-accel/personInferenceDemo.elf`；FPGA BIT没有变化，无需重新编译硬件。仅运行电脑程序不会更新板内网页或抓拍格式。
2. 电脑有线IP保持192.168.0.3/24。双击 `05_千兆以太网事件接收.cmd` 并保持运行；如防火墙询问，允许在该有线网络接收板卡连接。接收TCP8091，图片/事件HTTP8092，分别监听有线IP及本机127.0.0.1。
3. 打开原板载网站并按Ctrl+F5，在“最近事件”查看新发生的报警。电脑事件页 `http://127.0.0.1:8092/` 继续可用。
4. 实时视频另运行06；它不负责事件存档。05和06可同时运行。

图片与事件仍存到 `记录/以太网事件/` 的SQLite、CSV及BMP中。网页只显示本次开机最近16条板内事件，电脑接收页显示最近100条，SQLite/CSV保留全部已接收历史。

## 为什么此前是灰度

此前软件主动把彩色检测输入按 `(77R+150G+29B)/256` 转成灰度，目的是减少事件队列和上传量，并非摄像头或千兆网口的限制。新版从同一检测输入的相同位置复制RGB三通道，单图由5184字节增至15552字节，16条待确认队列增加165888字节DDR。总软件链接占用17085040字节/32MiB（50.92%），不是FPGA片内RAM增加。

同帧含义：状态变化分支中，事件帧号和RGB检测输入一并捕获，不使用稍后的视频画面替代。图片保留既有96×54尺寸，放大不会增加细节，旧灰度记录也不能恢复成原始彩色。

## 匹配和异常

- 原网页按板卡上报会话、事件编号、目标编号、帧号、开机毫秒和状态匹配电脑存档，防止板卡重启后的同编号事件误配旧照片。
- 接收程序未启动时提示启动05；尚未入库时提示等待电脑保存。既有事件文字记录仍可读取。
- 新协议EVT3传RGB，接收端也支持EVT2灰度。新固件必须配本次接收程序，旧接收程序不认识彩色报文。
- 入库后才确认、重传去重和16条队列保持。未确认队列不跨板卡断电，队满会计入dropped。
- 网页从电脑有线IP读取照片；查看网站的设备也需能访问该IP的8092端口。浏览器跨域仅允许板载网站来源。
