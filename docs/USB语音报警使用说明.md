# 电脑USB语音报警

当前选择：板卡原有USB串口 → 电脑程序 → 另一块USB转TTL → SYN6288。
不使用J28语音信号，不需要为本方案重新编译、下载BIT/ELF或写Flash。原V12和当前J28候选均有配套串口遥测。
仅新增电脑端工具，不占用额外FPGA逻辑/RAM。电脑必须保持开机并运行本程序。

## 接线

| USB转TTL | SYN6288 |
| --- | --- |
| VCC，跳线选择5V | VDD |
| GND | G |
| TXD | RXD |
| RXD | TXD，用于回包 |

BY留空。喇叭保持原配插座连接。转接器USB与板卡原有USB都插电脑，不把语音数据线接J28/J8，不并联另一组5V电源。

## 启动

1. 关闭占用COM15的串口助手。两个COM口也不能被其他程序同时打开。
2. 如需单句检查，先退出正在运行的02监听，再双击`03_USB_Voice_Test.cmd`，按提示输入语音COM口（当前COM15）。应播放“有人跌倒！请注意！”。程序观察回包10秒后结束；回包不等于实际已出声，需要听声音确认。02和03不能同时占用COM15。
3. 确认板卡正在运行识别程序，并用原有USB下载/串口接口连接电脑。
4. 双击`02_USB_Voice_Alarm.cmd`。先输入语音COM口，再输入板卡原有COM口，两者必须不同。程序启动时会列出当前端口及设备名称。不要把COM15同时填给板卡。
5. 看到“已收到有效板卡数据，正在监测红框”后，才算数据链路已连接。

也可以在此目录运行（COM7仅为板卡口示例，请用实际端口）：

```powershell
python tools/usb_voice_alarm.py --voice-port COM15 --board-port COM7
```

脚本使用当前Python环境已安装的pyserial。若其他电脑提示缺少serial，安装`python -m pip install pyserial`。

## 报警规则

- 读取板卡原有460800波特率、8N1的`@V6`遥测，校验长度、CRC和状态字段。
- 当前任一`tracks[].state == 2`即红框，与`live_camera.cc`绘制框使用的visible_state一致。
- 首次出现红框立即发送固定文字：**有人跌倒！请注意！**。每条指令加`[v16]`，设置厂家手册允许的最大音量16；该标记不朗读。不额外添加提示词或启动语音。
- 持续红框时，每15秒最多发送一次，多个同时红框合并播报。
- 有效数据中不再有红框，停止后续重播；已经开始的一句会自然播完。下一次重新出现红框立即播报。
- 只收到黄框、绿框、历史events或单独的alarm_latched，不触发播报。
- 只有新收到的有效数据才能触发播报；断流时不按旧红框无限重播。5秒没有有效数据会显示提示。
- 模块回包41=接收成功、45=接收失败、4F=空闲状态；程序显示回包，供现场核对。
- Ctrl+C退出并释放两个COM口；USB掉线或串口错误后程序退出，恢复连接后重新启动。

## 验收

先普通站立/黄框确认不播报，再红框确认播报指定句。保持红框20秒确认约15秒重播一次；恢复正常后确认不再重播，再次红框确认重新播报。断开板卡数据连接时，程序应提示无有效数据且不继续重播旧报警。

如果页面能访问而程序收不到数据，检查板卡原有USB串口是否接好、COM口是否正确。程序当前以串口为数据源，不会自动改用网页。

离线测试：`python tools/test_usb_voice_alarm.py`，使用模拟串口，不连接设备、不发声、不下载板卡。
